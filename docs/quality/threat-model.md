# Модель угроз

> Роль: Quality & Safety · Границы продукта — из [PRD](../prd.md), раздел 4 (MVP)
> Статус: **сверить с `docs/ai-pipeline.md`, когда он появится**

В MVP продавец загружает CSV до 100 отзывов и получает отчёт: проблемы по
товарам, цитаты, серьёзность, зону ответственности и подсказки действий.
Ответы покупателям, публикация и внешние действия в MVP **не выполняются**.

Отсюда главное свойство с точки зрения безопасности: **текст отзыва пишет
кто угодно**, а **по отчёту продавец принимает решение**. Цель атаки —
не опубликовать что-то от имени продавца, а исказить отчёт: спрятать
серьёзную проблему, поднять мелкую, подсунуть ссылку или вымышленный вывод.

## Границы доверия

```text
 НЕДОВЕРЕННОЕ                     СИСТЕМА                                   ПРОДАВЕЦ
 ─────────────                    ───────                                   ────────
 CSV: текст отзыва,  ──► проверка ──► подтверждение ──► модель ──► JSON ──► отчёт ──► решение
 product_id, оценка      строк        состава строк     (без         проверка        человека
 (до 100 строк)          (PRD, шаг 2)  человеком        инструментов) схемы и цитат
```

## Точки входа недоверенного текста

| # | Точка входа | Кто контролирует | Что попадает к модели | Права модели в этой точке | Что будет, если модель обманут | Мера защиты |
|---|---|---|---|---|---|---|
| E1 | **Текст отзыва** (`text`) | Любой покупатель или бот | Целиком | Вернуть JSON по схеме: проблемы, цитаты, серьёзность, зона, флаги | Пропущен или занижен критический сигнал; завышена мелочь; в отчёте — ссылка или чужой текст; вымышленная цитата | Текст в отдельном блоке «данные, не инструкции»; флаг `has_instruction`; проверка схемы; цитата проверяется как подстрока отзыва; порядок отчёта считает код, а не модель |
| E2 | **Идентификаторы и оценка** (`platform`, `review_id`, `product_id`, `rating`) | Тот, кто готовил файл | `product_id` и оценка как контекст | Только чтение | Длинная строка или инструкция в `product_id`; подмена товара, чтобы смешать группы | Проверка формата на шаге 2 PRD (длина, допустимые символы, оценка 1–5); группировку по товару делает код, не модель |
| E3 | **Файл целиком** (CSV) | Пользователь системы | Через E1–E2 | — | Больше 100 строк, огромный текст, неверная кодировка — расход бюджета; формулы в ячейках (`=HYPERLINK(...)`) при выгрузке отчёта | Лимиты PRD: ≤ 100 строк, предел длины текста; ошибочные строки показываются; при экспорте ячейки, начинающиеся с `= + - @`, экранируются |
| E4 | **Необязательная дата** (`date`) | Тот, кто готовил файл | Нет | — | Неверный формат ломает разбор | Проверка формата на шаге 2 |

Вывод модели (O1) — тоже точка риска: он идёт в отчёт. Он проверяется
схемой, цитаты — сравнением с исходным текстом, текст экранируется при
выводе в UI. Отзыв без подтверждённой цитатой проблемы не показывается
как обнаруженная проблема (правило PRD).

**Вне MVP** (появятся точки входа, когда войдут в скоуп): автоматический
сбор отзывов через API площадок, имена авторов и комментарии под отзывом,
черновики и публикация ответов, задачи во внешних системах. При включении
любой из них модель угроз пересматривается до реализации.

## Права модели — по минимуму

- Модель **не имеет инструментов**: не ходит в сеть, не вызывает API, не
  пишет в БД. Она только возвращает JSON по схеме.
- Модель **не решает порядок отчёта**: приоритет (серьёзность, затем
  частота) считает код по её разметке.
- Модель **не исключает отзывы**: пометка `suspicious` — только флаг,
  подсчёт делает код, помеченные отзывы остаются в нём (PRD).
- Модель **видит один пакет одного продавца** — чужих данных в контексте нет.
- Худший результат успешной атаки — неверный отчёт; продавец видит цитаты
  и может проверить основание до действия.

| **LLM03 Supply Chain** | Подмена модели или зависимостей, недоступность провайдера | Версии зависимостей закреплены; модель фиксирована по версии; план деградации (AI Engineer) | ревью `requirements*.txt` |
| **LLM04 Data and Model Poisoning** | Накрутки раздувают или топят проблему; порча golden dataset | Помеченные отзывы показываются отдельным числом, а не удаляются; изменения датасета — только PR с ревью; тест датасета в CI | gd-0010, gd-0036, gd-0053, gb-03 |
| **LLM05 Improper Output Handling** | HTML/JS из отзыва в цитате исполняется в UI; формулы в экспорте | Экранирование при выводе; проверка схемы; экранирование CSV | новая запись с `<script>` в тексте |
| **LLM06 Excessive Agency** | Система сама что-то меняет или отправляет | В MVP нет внешних действий: только отчёт, действие выбирает человек | интеграционный тест: разбор не вызывает внешних сервисов |

| **LLM08 Vector and Embedding Weaknesses** | Если группировка пойдёт через эмбеддинги — отзыв, подобранный, чтобы «прилипнуть» к чужой группе | Группы только внутри `(platform, product_id)`; продавец видит цитаты каждой группы | решение после `ai-pipeline.md` |

| **LLM10 Unbounded Consumption** | Пакет больше 100 отзывов, сверхдлинные тексты, повторы запросов — счёт за токены | Лимиты PRD: 100 строк, 180 с, 50 ₽ на пакет; при превышении — понятная ошибка, отчёт помечен неполным | тест лимитов |

## Требования регулятора

152-ФЗ «О персональных данных»: если в текстах отзывов встречаются
персональные данные покупателей, система не хранит их дольше разбора и не
выводит в отчёт сверх цитаты-основания.
