# Definition of Done артефактов команды

> Роль: Quality & Safety · Лаба 2 · Заменяет [dod-draft.md](dod-draft.md)
> Статус: **на согласовании с командой** — отметка о согласовании ставится в PR каждой роли.

DoD — спецификация для автопроверки. Каждый пункт проверяется одним из
трёх способов: **есть / нет**, **число**, **ссылка**. Пункт, который нельзя
проверить так, переписывается.

Обозначения колонки «Как проверить»: 🤖 — машиной (команда, скрипт, CI),
👀 — чтением, но ответ однозначный (есть / нет, число).

## 0. Общие для всех артефактов

| # | Критерий | Как проверить |
|---|---|---|
| G1 | Файл лежит по пути из задания лабы и указан в README → «Структура репозитория» | 🤖 путь существует; 👀 строка в README |
| G2 | Термины предметной области из артефакта определены в `docs/glossary.md` | 👀 каждый термин находится поиском в глоссарии |
| G3 | PR назван `LabN: [Role] — …`, CI на нём зелёный | 🤖 статус проверки `Code Quality` |
| G4 | Нет секретов и персональных данных | 🤖 поиск по `password`, `token`, `api_key`, e-mail, телефонам — 0 находок вне `.env.example` |
| G5 | Диаграммы хранятся исходником (PlantUML), а не только картинкой | 🤖 рядом с картинкой есть `.puml` |

## 3. Как DoD используется

- Перед открытием PR автор проходит свои строки DoD и отмечает их в описании PR.
- Quality проверяет PR по DoD до мёржа; невыполненный пункт — комментарий в PR со ссылкой на строку этого файла.
- Критерий, который оказался непроверяемым, переписывается в этом файле отдельным PR.
