# Тест-план

> Роль: Quality & Safety · Лаба 2 · Статус: **на согласовании с Delivery и AI Engineer**

Цель — каждая метрика из [success-criteria.md](success-criteria.md) и каждая
угроза из [threat-model.md](threat-model.md) проверяется на своём уровне,
а в CI попадает всё, что можно проверить без человека.

## Уровни тестирования

| Уровень | Что проверяем | Чем | Где лежит | С какой лабы |
|---|---|---|---|---|
| **Статика** | Стиль, ошибки, форматирование | Ruff (`check`, `format --check`) | `backend/` | уже работает |
| **Данные** | Golden dataset читается, улики — цитаты из текста, покрытие не просело | pytest, без модели | `backend/tests/test_golden_dataset.py` | **уже работает (лаба 2)** |
| **Unit** | Проверка CSV по PRD: обязательные столбцы, ≤ 100 строк, оценка 1–5, пустые тексты и повторные `review_id` внутри площадки показываются, а не отбрасываются молча; нормализация текста; обёртка недоверенного текста перед моделью; валидация JSON-ответа модели по схеме; проверка цитат как подстрок; группировка по `(platform, product_id, code)`; порядок отчёта (серьёзность, затем частота); частота и доля по разным отзывам | pytest, модель подменена заглушкой | `backend/tests/unit/` | лаба 3 |
| **Контракт** | Ответы API соответствуют `api/openapi.yaml`; enum-поля совпадают с golden dataset | pytest + проверка по OpenAPI-схеме | `backend/tests/contract/` | лаба 3 |
| **Интеграция** | API + PostgreSQL в compose: загрузка CSV → проверка строк → подтверждение → разбор → отчёт; при ошибке модели или превышении бюджета отчёт помечен неполным; помеченные отзывы остаются в подсчёте | pytest + `docker compose -f compose.dev.yml`, модель — заглушка с фиксированными ответами | `backend/tests/integration/` | лаба 3–4 |
| **Evals** | Качество разбора на golden dataset (выборка `test`): полнота и точность проблем, группировка внутри товара, пропуски `critical`, порядок отчёта на кейсах-пакетах, существование цитат, зона ответственности, пометка накруток | evals-раннер (pytest) с настоящей моделью; без LLM-judge — все эталоны проверяются сравнением | `evals/` | лаба 3 |
| **Безопасность** | Атаки из threat model: инструкции в отзыве, утечка системного промпта, ссылки, манипуляция приоритетом, формулы в CSV, перегрузка | тот же evals-раннер на срезе `tags: attack` + отдельные тесты лимитов и экспорта | `evals/`, `backend/tests/security/` | лаба 4 |
| **Smoke на проде** | `/health` отвечает 200 после деплоя | curl в шаге деплоя | `.github/workflows/` | лаба 4 |
| **Ручное** | Прохождение UC человеком не из команды; смысл цитат на расхождениях с эталоном; учебный эксперимент North Star (PRD, раздел 5) | чек-лист | `docs/quality/` | каждая лаба |

## Что идёт в CI

| Задача CI | Событие | Время | Блокирует мёрж | С какой лабы |
|---|---|---|---|---|
| Ruff + unit + данные + контракт | каждый PR и push в `main` | < 2 мин | да | данные — **сейчас**, остальное — лаба 3 |
| Сборка Docker-образа | каждый PR | < 3 мин | да | уже работает |
| Интеграция в compose | каждый PR | < 8 мин | да | лаба 3–4 |
| Evals: быстрый срез (≈ 15 записей `test`: все `critical` и `attack` + по одной на код) | PR, меняющий `backend/app/ai/**`, промпты или модель | < 3 мин | да, если провалена метрика с целью 0 / 100 % | лаба 3 |
| Evals: полная выборка `test` + кейсы-пакеты, замер времени и стоимости пакета | ночью и перед сдачей лабы | < 15 мин | нет, отчёт в PR / issue | лаба 3 |
| Безопасность (срез `attack`) | вместе с быстрым срезом evals | входит в него | да | лаба 4 |
| Smoke на проде | после деплоя из `main` | < 1 мин | откат деплоя при провале | лаба 4 |

## Правила

- **Тест до кода.** Новая функция пайплайна приходит с записью в golden
  dataset или unit-тестом, который без неё падает.
- **Ошибка → регрессия.** Найденная человеком ошибка разбора становится
  записью golden dataset в том же PR, что и исправление.
- **Модель в unit и интеграции — заглушка.** Настоящая модель вызывается
  только в evals: так тесты детерминированы и бесплатны.
- **Секреты.** Ключ модели — секрет GitHub `LLM_API_KEY`; evals из PR
  с форков не запускаются.
- **Настройка отдельно от проверки.** Промпты настраиваются только на
  записях `split: tune`; метрики, которые идут в отчёт, считаются на `test`.
- **Порог падения.** Метрика с целью 0 или 100 % — любое отклонение
  блокирует мёрж; остальные — падение > 5 п. п. против `main` требует
  объяснения в PR.
- **Отчёт.** Evals публикуют таблицу метрик в комментарий PR и сохраняют
  JSON с результатами как артефакт сборки.

| Уровень | Пишет | Проверяет |

| Статика, сборка, интеграция, smoke | Delivery | Quality |

| Данные, evals, безопасность | Quality | AI Engineer |
| Ручное прохождение UC | Product | Quality |
