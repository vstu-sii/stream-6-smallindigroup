## Хватает ли объёма для устойчивой метрики

- **Recall и precision проблем** считаются по парам «запись — код»: в
  наборе 41 такая пара. Одна ошибка сдвигает метрику на 2,4 п. п.; 95 %
  доверительный интервал для recall 0,85 на 41 паре — примерно ±0,11.
  Этого достаточно, чтобы отличить рабочий пайплайн (≥ 0,85) от
  нерабочего (≤ 0,6), но мало, чтобы различать версии промпта с разницей
  в 3–5 п. п.
- **Метрики с целью «0» или «1,00»** (пропуск `critical`, исполненная
  инъекция) считаются по каждому случаю отдельно: одна ошибка — провал,
  объём здесь не влияет на вывод.
- **Узкие срезы** (накрутки, нейтральная тональность — по 4–6 записей)
  ориентировочные: по ним смотрим ошибки глазами, а не сравниваем числа.
- **План роста:** v1.1 — 80 записей к лабе 4 (за счёт `public_review` и
  `interview`), затем рост атакующего среза по итогам red team.

## Кейсы на контекст

Отчёт о проблемах строится не по одному отзыву, а по набору — это и есть
контекст ответа. Поэтому кейсы `batches-v1.0.jsonl` проверяют, что
система сделала с набором:

- `groups` — какие отзывы она обязана объединить под каким кодом;
- `top` — порядок проблем в отчёте;
- `excluded` — отзывы, которые не должны попасть в подсчёт (накрутки);
- `must_flag` — отзывы, которые обязаны быть в отчёте отдельно (`critical`).

Отзывы в кейсах — ссылки на `id` из `golden-v1.0.jsonl`, текст не дублируется.

## Владелец и процесс пополнения

1. **Владелец** — роль Quality & Safety. Только она мёржит изменения в набор.
2. **Источник новой записи** — UC, интервью, найденная ошибка системы
   или атака. Каждая ошибка системы на проде, найденная человеком,
   становится записью в наборе (регрессия).
3. **Добавление** — PR, в котором запись проходит тест формата и у неё
   заполнены `uc`, `source.basis` и `tags`.
4. **Ревью разметки** — второй участник команды проверяет эталон;
   спорный случай решается с Product и, если нужно, уточняет глоссарий.
5. **Версии** — добавление записей повышает минорную версию
   (`v1.1`), изменение полей или таксономии — мажорную (`v2.0`).
   Старые файлы не удаляются, метрики сравниваются на одной версии.
6. **Данные** — без имён, никнеймов, номеров заказов и адресов авторов;
   правила происхождения — в [плане](../golden-dataset-plan.md#происхождение-данных-что-можно-и-чего-нельзя).
