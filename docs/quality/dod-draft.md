# Заготовка DoD артефактов к лабе 2

> Роль: Quality & Safety · Лаба 1 · Статус: **черновик, согласовать с командой**
> Финальная версия — [`dod.md`](dod.md) (лаба 2). Этот файл сохранён как история.

DoD — спецификация для автопроверки. Каждый пункт проверяется ответом
«есть / нет», числом или ссылкой. Пункт, который нельзя проверить, —
переписываем.

## Общие для всех артефактов

- [ ] Файл лежит по пути, указанному в задании лабы 2, и упомянут в README (раздел «Структура репозитория»)
- [ ] Все термины предметной области из артефакта есть в `docs/glossary.md`
- [ ] PR назван `Lab2: [Role] — …`, CI на нём зелёный
- [ ] В артефакте нет секретов и персональных данных (проверка: поиск по `password`, `token`, `@`, телефонным номерам)

## Product / VO

| Артефакт | Критерии готовности |
|---|---|
| Use cases — `docs/use-cases/` | Каждый UC содержит актора, предусловие, основной сценарий и минимум 1 альтернативный; ≥ 3 UC; use-case диаграмма в PlantUML лежит рядом и рендерится; есть отметка, кто не из команды прожил UC и без каких вопросов |
| Роадмап — `docs/roadmap.md` | Есть раздел «Скоуп MVP» и раздел «Не-скоуп» с ≥ 3 пунктами; у каждого пункта скоупа — лаба, в которой он появится |
| Глоссарий v2 — `docs/glossary.md` | ≥ 25 терминов; есть термины архитектуры и пайплайна (≥ 5 новых против лабы 1); каждый термин из UC и ADR определён |
| ADR — `docs/adr/` | У каждого ADR заполнены поля «Контекст», «Решение», «Альтернативы», «Цена решения»; статус `accepted` или `rejected` |

## AI Engineer

| Артефакт | Критерии готовности |
|---|---|
| Схема AI-пайплайна — `docs/ai-pipeline.md` | Есть схема шагов от сырого отзыва до черновика ответа; для каждого шага указан вход, выход и чем меряется (ссылка на метрику из `success-criteria.md`); отмечено, где текст отзыва изолирован от инструкций модели |
| Решение по модели — `docs/model-candidates.md` | Раздел «решение» с выбранной моделью, ценой разбора 1 отзыва в ₽ и сравнением ≥ 2 кандидатов на golden dataset v0.x |
| Спайки — `docs/experiments/lab2.md` | Для каждого допущения: гипотеза, что сделали, результат с числом, вывод; ноутбук приложен и запускается |
| Контракт AI-API — `api/openapi.yaml` | Файл валиден по OpenAPI 3 (проверка линтером); схема ответа анализа содержит поля `sentiment`, `problems[].code`, `problems[].evidence`, `severity`, `suspicious`, `has_instruction` — те же, что в golden dataset |

## Delivery

| Артефакт | Критерии готовности |
|---|---|
| C4 + aact — `docs/architecture/` | Context- и container-диаграммы в PlantUML; `aact check` — 0 violations (лог в PR) |

| Схема данных — `database/schema.sql` | Применяется к пустой PostgreSQL без ошибок; ERD лежит рядом; есть таблицы отзывов, проблем и аудита подтверждений ответа |
| Compose-скелет — `compose.dev.yml` | `docker compose -f compose.dev.yml up` поднимает все сервисы за ≤ 10 минут, health-check каждого — `healthy` |

## Quality & Safety

| Артефакт | Критерии готовности |
|---|---|
| DoD — `docs/quality/dod.md` | Для каждого артефакта лабы 2 есть ≥ 2 проверяемых пункта; согласован с командой (отметка в PR) |
| Golden dataset v1 — `docs/quality/golden-dataset/` | ≥ 30 записей; каждая проходит валидацию схемы; каждый UC покрыт ≥ 3 записями; ≥ 20 % краевых и атакующих; каждый код таксономии — ≥ 3 записи |
| Тест-план — `docs/quality/test-plan.md` | Уровни тестирования (unit, интеграционные, evals) и для каждого — что запускается в CI и при каком событии |
| Модель угроз — `docs/quality/threat-model.md` | Перечислены все точки входа недоверенного текста (минимум: текст отзыва, имя автора, ответ площадки); для каждой — угроза, мера защиты и пример в golden dataset |

## Открытые вопросы к команде

1. Сегмент: продавец маркетплейса или владелец кафе — от этого зависят примеры и таксономия.
2. Порог стоимости разбора отзыва (сейчас 0,50 ₽) — согласовать с AI Engineer после оценки токенов.
3. Кто, кроме Quality, проверяет разметку golden dataset.
