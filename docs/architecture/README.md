# Архитектура Reviews Analyzer

[C4 Context](context.puml) показывает продавца и границу системы. Маркетплейсы указаны в PRD как источники подготовленных файлов. Сценарий MVP начинается с загрузки файла продавцом. [C4 Container](container.puml) описывает обработку и хранение данных. Границы контейнеров зафиксированы в [ADR-002](../adr/002-dev-topology.md).

После проверки файла пользователь подтверждает корректные строки. API сохраняет пакет и ставит задание. Воркер отправляет порции до 10 отзывов в `POST /internal/ai/reviews/analyze` по [контракту AI Engineer](../../api/openapi.yaml) и проверяет цитаты по диапазонам `[start, end)` в кодовых точках исходного текста. Группы считаются по `(platform, product_id, code)`, а помеченные отзывы остаются в подсчёте. Неопределённые или неразобранные отзывы отражаются признаком неполноты в [контракте отчёта](../../api/report.openapi.yaml).

Ключ идемпотентности содержит номер порции и попытки, например `batch-017:chunk-01:attempt-1`. При сетевом повторе сохраняются тело и ключ. При новой генерации после окончательной повторяемой ошибки увеличивается номер попытки, если позволяют время и бюджет. Необязательная дата нужна импорту и сохраняется в БД, а внутренний AI-API получает только поля, описанные в контракте.

## Проверка архитектуры

Из корня репозитория выполните `npx --yes aact@3.0.0-beta.29 check`. Конфиг читает Container-диаграмму и проверяет зависимости между контейнерами. Команда `npx --yes aact@3.0.0-beta.29 model` показывает прочитанные элементы и связи.

## Что запущено в dev-стенде

| Сервис | Поведение в лабе 2 |
| --- | --- |
| `web` | Отдаёт локальный HTML-прототип с демонстрационным CSV и отчётом. |
| `api` | Сохраняет маршруты каркаса лабы 1. |
| `worker` | Проверяет доступность сервисов хранения и модели. |
| `model` | Возвращает ответ readiness-заглушки без загрузки весов. |
| `storage` | Проверяет возможность SQL-запроса к схеме PostgreSQL. |
| `db` | При первом запуске применяет начальную SQL-схему к новому тому. |

Запустите `docker compose -f compose.dev.yml up -d --wait` и посмотрите статусы через `docker compose -f compose.dev.yml ps`. Веб-интерфейс и API доступны с хоста по портам 8080 и 8000. Воркер, модель, хранилище и БД доступны в сети Compose.

Остановить стенд можно командой `docker compose -f compose.dev.yml down`. При повторном запуске используется тот же том базы. Для отдельного чистого прогона задайте новое имя проекта через `-p`, при свободных портах.

## Сценарии прототипа

Скачайте пример CSV и выберите его в браузере. Прототип покажет двенадцать корректных строк и две ошибки. Подтвердите корректные строки, чтобы открыть демонстрационный отчёт. Ссылка «Ткань линяет после стирки» открывает карточку с цитатами и идентификаторами трёх отзывов.
