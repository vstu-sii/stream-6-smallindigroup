# Итоги проверки прототипа и план спринта 4

**Reviews Analyzer · Лабораторная № 3 · Product / Vision Owner**

Продавец может изучить демонстрационный отчёт и по одной группе выбрать проверку партии. Получить отчёт именно по своему CSV пока нельзя. Переход от подтверждения строк к анализу пакета — первая недостающая часть сквозного пути. Результаты проверок ниже относятся к прототипу и двум воспроизводимым прогонам правил. Продуктовую приёмку по полному пути оставляем открытой.

## Сквозная проверка пути продавца

1. **Вход.** В браузере открыта «Загрузка отзывов», кнопка подтверждения выключена. Локально обработчику переданы [пример команды](../frontend/prototype/example.csv) и однострочный контроль с обязательными полями: `yandex_market,YM-CONTROL,YM-0,5,Все подошло` в порядке `platform,product_id,review_id,rating,text`. Дата в контроле отсутствует.
2. **Подтверждение и анализ.** В компонентной проверке для примера показаны 12 пригодных строк и две ошибки, для контроля — одна пригодная и ноль ошибок. После подтверждения оба ввода приводят к одному `#report`. Обработчик меняет раздел страницы, не передавая пакет на анализ. Для полностью ошибочной строки подтверждение остаётся недоступным. [Валидатор](../frontend/prototype/csv.js) · [Обработчик формы](../frontend/prototype/prototype.js)
3. **Группы и порядок.** В публичном интерфейсе выбран доступный без загрузки пункт «Отчёт по проблемам». Появились 12 отзывов, три группы, одна пометка. Показаны два товара на двух площадках. У первой группы WB-104 — три жалобы из шести и высокая серьёзность. Доля 50% сходится с тремя разными ID в карточке. Два следующих заголовка не открываются. Сценарий с редким критическим сигналом проверен отдельно по `gb-01` в evals.
4. **Цитата и решение.** В браузере открыта «Ткань линяет после стирки». Для WB-R102 фрагмент сверен со строкой примера: в полном тексте дополнительно указаны 30 градусов. На основании жалобы выбран шаг — проверить образец партии WB-104 при режиме с этикетки. Полный отзыв для такой сверки пришлось прочитать вне интерфейса. Ссылка «К отчёту» вернула к прежним числам.
5. **Пометка.** У OZ-207 показан один помеченный отзыв из шести. Счётчик не открывает запись. Через отчёт нельзя проверить ID, полный текст и вклад помеченной жалобы. [Экраны прототипа](../frontend/prototype/index.html)

## Предложение к спринту 4

Приоритет P0 означает препятствие для доверия к отчёту, P1 — следующий обязательный шаг для завершения сценария. Роли ниже предложены для обсуждения. Подтверждения команды о распределении и сроках на дату проверки нет.

| Очередь и задача | Предлагаемая ведущая роль | Результат, по которому Product принимает работу |
|---|---|---|
| P0 · S4-01. Связать загрузку, подтверждение, разбор и чтение | Delivery, с AI Engineer для вызова модели | Два разных CSV дают два различимых пакета. Для каждого до подтверждения виден состав. После отдельного запуска видны обработанные и необработанные строки. Метод чтения возвращает сохранённый результат своего пакета. При ошибке видна неполнота или причина отказа. Обновление страницы не требует нового вызова модели. |
| P0 · S4-02. Вернуть редкие критические сигналы в очередь проверки | AI Engineer, с Quality для сверки | На том же `full` достигнуты цели 0 пропусков критических и 0 нарушений порядка. В интерфейсе на данных `gb-01` возможный риск виден до более частой жалобы. Продавец может открыть основание. |
| P0 · S4-03. Сделать каждую группу проверяемой | Delivery ведёт задачу. AI Engineer проверяет основания и зону | У каждой группы открываются ID, цитаты и полные тексты. В `gd-0033` и `gd-0036` нет ложных дефектов и рекламного фрагмента в выводах. У `gd-0050` зона `null`. Для WB-R102 доступны условия стирки. |
| P1 · S4-04. Сверить группы и сохранить помеченные жалобы | AI Engineer ведёт задачу. Delivery отвечает за просмотр, Quality — за сверку (предложение) | Сравнить с правилами полноту, точность, состав групп и пометки на тех же срезах. Ориентиры — цели PRD и Quality. На `gb-02` разделены товары, на `gb-03` открывается список пометок и видна жалоба `gd-0053` в своей группе. Частоты при просмотре не меняются. |
| P1 · S4-05. Принять полный путь и измерить пользу | Product, с Quality для независимой сверки | После интеграции повторить из браузера все шесть UC, включая новый CSV и неполный результат. На полном пакете 100 отзывов зафиксировать время от запуска до готового отчёта, расходы всех модельных шагов с повторами. Для North Star выполнить пять контрольных заданий по протоколу PRD, записать решения проверяющего. |

S4-01 и работа с ответами в S4-02/S4-03 могут начаться параллельно. Для сквозной приёмки нужны их результаты и просмотр пометок из S4-04. В проекте контракта отчёта уже есть счётчики по товару, цитаты и признак неполноты. Для UC-02 и UC-06 Delivery предстоит определить, как интерфейс получит число необработанных отзывов, полный текст и доступные записи по пометке. Одного агрегированного счётчика для этих действий недостаточно.
