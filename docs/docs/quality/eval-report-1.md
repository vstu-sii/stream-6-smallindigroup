# Где ошибается Reviews Analyzer

**Продуктовый разбор первого прогона Quality · 24 ноября 2026 · Product / Vision Owner**

Продавцу нельзя полагаться на этот baseline при выборе первой проверки. Правила пропустили все четыре критических сигнала и приписали высокую серьёзность положительному отзыву. До использования отчёта для решений нужны обнаружение редкого риска, проверка смысла цитаты и возможность прочитать исходный отзыв.

## Что измерено

Предсказатель `rules-v0` получает только поля входа. Он ищет выражения в тексте и присваивает код, серьёзность и зону по правилам. Группы и порядок вычисляет сборщик самого eval-раннера. На Render показан отдельный демонстрационный отчёт.

В наборе v2.0 — 53 записи. Одиночные метрики полного среза посчитаны на 41 отзыве `test`. Пять пакетных эталонов используют перечисленные в них ID, включая записи из `tune`. В локальном повторе на Python 3.10.5 совпали списки входов, значения метрик, результаты проверок порогов и списки ошибок в JSON обоих прогонов Quality от 22 ноября. Команды из корня репозитория:

```bash
python -m tests.evals.run --slice fast
python -m tests.evals.run --slice full
```

## Очерёдность для AI Engineer

1. **До приёмки отчёта:** добиться нуля пропусков `critical` и нуля нарушений порядка. На тех же данных отдельно проверить отсутствие ложной тревоги на `gd-0033` и рекламного вывода на `gd-0036`. Исправление высокой частоты обычных ошибок не компенсирует пропущенный опасный сигнал.
2. **Далее:** восстановить перефразы, вторую проблему в одном отзыве и неопределённую зону. На случаях со встроенной командой проверять одновременно распознавание инструкции и сохранение реальной жалобы. Сравнить нового предсказателя с правилами на неизменных срезах, включая точность, полноту и состав групп. Для UC-06 отдельно проверить полноту пометок и сохранение жалоб.
3. **Временно допустимо в демонстрации:** неточная тональность при верно переданных проблемах, округление 2/6 до 33% рядом с исходной дробью, ручная сверка неоднозначного случая. Долг по тональности допустим, пока она не управляет приоритетом. Потеря основания, ложный дефект или исчезновение критического сигнала блокируют приёмку.
