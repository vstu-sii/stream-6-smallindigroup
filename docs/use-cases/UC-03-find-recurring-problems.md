# UC-03. Найти повторяющиеся проблемы товара

**Актёр:** продавец, изучающий результаты разбора.

**Цель:** увидеть повторяющиеся жалобы по конкретному товару и понять, как часто они встречаются.

**Контекст:** покупатели описывают похожие недостатки разными словами. Продавцу нужен общий список проблем, в котором не смешаны разные товары и площадки.

**Предусловия:** есть отчёт по UC-02. Для окончательного подсчёта пакет разобран полностью; неполный результат явно обозначен.

**Триггер:** продавец выбирает товар и площадку или открывает группу в отчёте.

Общие правила данных и отчёта определены в [UC-01](UC-01-upload-and-validate.md#общие-правила).

## Основной сценарий

### Шаги

1. Продавец выбирает нужные площадку и товар. Система показывает число подтверждённых отзывов выбранной товарной позиции.
2. Система показывает группы проблем: название категории, число разных отзывов и долю от всех принятых отзывов этого товара на этой площадке.
3. Продавец открывает группу. Система показывает цитаты и идентификаторы входящих отзывов, даже если жалобы сформулированы разными словами.
4. Продавец сопоставляет формулировки и понимает, какие отзывы посчитаны вместе. Он может открыть каждый исходный текст.
5. Продавец выбирает другой товар или площадку и получает их собственные группы и частоты. Повторная генерация отчёта не требуется.

## Альтернативы и исключения

- **2а. Жалоба повторяется внутри одного отзыва:** один код в этом отзыве добавляет одно упоминание. Дословное повторение фразы не увеличивает частоту.
- **2б. У отзыва несколько разных кодов:** он входит в соответствующие группы по одному разу. Сумма долей разных проблем может превышать 100%.
- **2в. Одинаковый `product_id` или код встречается на другой площадке:** группы остаются раздельными. Данные разных товаров также не объединяются.
- **2г. Код охватывает разные виды недостатков, например `material_quality`:** группа названа широкой категорией, а конкретные недостатки видны в цитатах. Общий код не выдаётся за доказательство одной причины дефекта.
- **2д. В выбранных отзывах жалоб не выделено:** система показывает число разобранных отзывов и отсутствие найденных проблем; группы не создаются искусственно.
- **2е. Есть подозрительные отзывы:** их жалобы остаются в группах, сами отзывы и число пометок доступны по UC-06. Знаменатель не уменьшается из-за подозрения.
- **2ж. Отчёт неполный:** число необработанных отзывов видно рядом с предупреждением. Для найденных групп можно показать цитаты и число уже выявленных упоминаний с пометкой о неполноте; итоговые доли до завершения разбора не выводятся.
- **3а. В группу ошибочно попала неподходящая жалоба:** продавец проверяет исходные тексты и не делает вывод об общей причине только по названию группы. Исправление таксономии и повторная обработка не выполняются скрытно.

## Результат

**Ожидаемый итог успешного прохождения:**

- Участник выбрал товар и площадку и определил, какие категории проблем встречаются в их отзывах.
- Для повторяющейся проблемы нашёл разные формулировки жалобы, объединённые в одну группу, и показал подтверждающие отзывы.
- Объяснил число упоминаний и долю: сколько разных отзывов содержит проблему и сколько всего отзывов принято по этому товару на этой площадке.
- Убедился, что данные других товаров и площадок посчитаны отдельно, а помеченные отзывы не исключены из общей частоты.

Если проблем не найдено, участник увидел это вместе с объёмом разбора. При неполном результате он распознал предупреждение; окончательные доли не были показаны.

## Как поймём, что работает

- Правильная группировка размеченных перефраз — ≥80% по определению PRD; пакетные проверки дополнительно сверяют состав групп.
- 0 групп, смешивающих разные товары или площадки.
- Число упоминаний равно числу разных отзывов с кодом; знаменатель включает отзывы без жалоб и подозрительные отзывы того же товара и площадки.
- Человек вне команды находит группу, показывает подтверждающие отзывы и объясняет число и долю без вопросов.


### Фактический протокол

Участник, не входящий в команду проекта, самостоятельно прошёл UC-03 на учебном макете. Для Wildberries / TOWEL-01 он нашёл группу „Задержка доставки“, открыл отзывы demo-002, demo-003 и demo-004 и показал разные формулировки одной проблемы. Он объяснил частоту: 3 разных отзыва из 5 принятых по этому товару на этой площадке, то есть 60%. Затем участник выбрал Ozon / TOWEL-01 и нашёл отдельную группу „Посторонний запах“: 2 из 3, примерно 66,7%. Он пояснил, что одинаковый product_id на разных площадках не объединяет товары, положительные и помеченные отзывы остаются в знаменателе, а просмотр фильтров не запускает новый анализ. Результат сценария достигнут; уточняющих вопросов — 0, подсказок — 0. Затруднений, потребовавших исправления, не возникло.
