# ADR-002. Контейнеры и границы доступа к данным

Статус — предложено для ревью Product и AI Engineer.

## Контекст

По PRD продавец загружает до 100 отзывов и получает отчёт. Лимит полного разбора — 180 секунд. Время ответа модели и выбранный способ её запуска уточняются в эксперименте AI Engineer.

## Решение

- API принимает пакет и отдаёт его состояние. Воркер выполняет разбор отдельно от запроса загрузки. Для MVP задания хранятся в PostgreSQL. Сервис хранения выдаёт задание атомарно, а воркер записывает результаты вместе со сменой статуса задания.
- Сервис хранения единолично подключается к PostgreSQL. API и воркер получают доступ к нужным операциям через внутреннюю сеть.
- Воркер обращается к модели через внутренний HTTP-интерфейс. Модель получает до 10 отзывов за запрос и возвращает наблюдения. Управление заданием, проверка цитат и группировка остаются в воркере. API отдаёт готовый или неполный отчёт через отдельный публичный контракт.
- Схема и прототип покрывают загрузку CSV, подтверждение корректных строк, отчёт и проверку цитат по PRD.

## Альтернативы

Рассматривались синхронный разбор в API и очередь сообщений. Первый вариант требует держать исходное HTTP-соединение до конца анализа. Очередь добавляет ещё один сервис и переносит часть состояния за пределы PostgreSQL.

## Цена решения

Появляются дополнительный HTTP-переход при доступе к данным, сервис хранения и опрос статуса с фронтенда. При реализации выдачи заданий понадобятся атомарный захват с ограниченным сроком, повторная выдача после сбоя и идемпотентная запись результата. Границы пересмотрим после измерения полного пакета и согласования AI-контракта.
