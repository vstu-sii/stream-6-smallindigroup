# Ревью ADR-002: контейнеры и границы доступа к данным

**Роль:** Product / Vision Owner.  
**Версия:** main, `1ced4b4d4e183aa812e99fbadba3738cbcce268f`.  
**Объект:** [ADR-002](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/docs/adr/002-dev-topology.md).  
**Заключение:** требуется уточнение контрактов хранения и чтения результатов по R1–R3. Статус исходного ADR — `proposed`.

## Результат проверки

| Критерий | Результат |

| Размещение неархитектурных решений | Выбор AI-подхода находится в [исследовании](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/docs/research.md) и [model-candidates.md](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/docs/model-candidates.md); скоуп — в [роадмапе](../../roadmap.md), метрики — в [PRD](../../prd.md) |

В рассмотренной версии `docs/adr/` содержит один архитектурный ADR. Перенос неархитектурных решений из этой папки не требуется. Проверка выполнена анализом документов; запуск системы и измерение AI-метрик в состав ревью не входили.

## R1. Сохранение результатов отдельных отзывов

**Связанные сценарии:** UC-02, UC-03, UC-05.  
**Адресаты:** Delivery, AI Engineer.

**Основание:** [AI-контракт](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/api/openapi.yaml#L327) определяет статусы `analyzed` / `needs_review` и поля отдельных проблем. В [схеме БД](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/database/schema.sql#L57) `severity` и `owner` определены на уровне группы; хранение соответствующих значений отдельных проблем и статусов разбора описано не полностью.

**Требуемое уточнение:** определить постоянный источник результатов отдельных отзывов и проблем, включая статусы, причины ручной проверки, серьёзность, зону ответственности и основания; установить связь этих результатов с группами.

**Критерий закрытия:** результаты с одинаковым кодом проблемы и различающимися `severity` / `owner`, а также состояние `needs_review`, восстанавливаются без повторного вызова модели. Групповые значения не подменяют исходные результаты.

## R2. Чтение исходных и помеченных отзывов

**Связанные сценарии:** UC-02, UC-05, UC-06.  
**Адресат:** Delivery.

**Основание:** [Report API](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/api/report.openapi.yaml#L12) содержит цитаты `ReviewEvidence` и счётчик `flagged_review_count`. Источник полного текста и перечня конкретных помеченных отзывов для интерфейса не определён.

**Требуемое уточнение:** определить контракт чтения полного отзыва, его идентификаторов, пометки и связанных результатов. Перечень помеченных отзывов должен включать записи без выделенных проблем.

**Критерий закрытия:** пользователь открывает полный исходный отзыв из отчёта и списка пометок; доступ ограничен владельцем пакета. Просмотр не запускает повторный анализ и не изменяет состав пакета или частоты.

## R3. Представление неполного результата

**Связанные сценарии:** UC-02, UC-03, UC-04.  
**Адресаты:** Delivery, AI Engineer.

**Основание:** [контракт отчёта](https://github.com/vstu-sii/stream-6-smallindigroup/blob/1ced4b4d4e183aa812e99fbadba3738cbcce268f/api/report.openapi.yaml#L56) содержит `incomplete`, но не определяет численный объём неполноты. Поле `review_share` обязательно и имеет числовой тип независимо от полноты результата.

**Требуемое уточнение:** определить источник и смысл счётчиков обработанных отзывов, записей для ручной проверки и записей без пригодного результата; установить представление долей при `incomplete=true`.

**Критерий закрытия:** состояния согласованы с размером принятого пакета; объём неполноты виден пользователю. Итоговые доли не отображаются до завершения разбора. Успешный результат `problems=[]` отличается от ошибки и `needs_review`.

## Повторная приёмка

Для закрытия замечаний необходимы уточнённые схемы или контракты со ссылками на соответствующую версию. Конкретный способ хранения и состав операций API определяются авторами технических документов.

Product повторно проверяет критерии R1–R3 и фиксирует итог приёмки в ADR-002. До принятия решения сохраняется статус `proposed`.
